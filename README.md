# DAYFLOW - 하루 루틴 분석 대시보드

매일의 루틴을 기록하고 실천율을 확인하는 브라우저 기반 대시보드입니다. HTML, CSS, 순수 JavaScript로 만들었으며 데이터는 브라우저의 `localStorage`에 저장됩니다. 서버나 API 키는 필요하지 않습니다.

## 프로젝트 구조

```text
dayflow/
├── index.html   # 화면 구조와 Chart.js 연결
├── style.css    # 반응형 화면 디자인
├── script.js    # 루틴, 날짜별 기록, 통계, 저장 로직
└── README.md    # 실행과 배포 안내
```

## 실행하기

1. 저장소 폴더에서 `index.html`을 브라우저로 엽니다. 또는 VS Code의 Live Server 확장 프로그램으로 `index.html`을 실행합니다.
2. 첫 방문에는 예시 루틴이 표시됩니다. 예시 루틴은 통계에 완료 기록이 있는 것처럼 반영되지 않으며, 수정하거나 삭제할 수 있습니다.
3. `루틴 추가`로 루틴을 만들고, 완료 버튼을 눌러 기록합니다. 날짜 화살표로 과거 기록을 확인하거나 수정할 수 있습니다.

Chart.js는 CDN에서 불러옵니다. 주간 그래프를 표시하려면 브라우저가 인터넷에 연결되어 있어야 합니다. 그래프를 제외한 기본 화면과 저장 기능은 로컬에서 동작합니다.

## 데이터와 통계

- 데이터는 현재 브라우저의 현재 웹 주소(origin)에 연결된 `localStorage`에 저장됩니다. 다른 브라우저나 기기와 자동으로 동기화되지 않습니다.
- 날짜별 완료 기록은 루틴 단위로 남습니다. 루틴을 삭제하면 삭제한 날짜부터 목록에서 숨겨지며, 삭제 이전의 기록과 통계는 보존됩니다.
- 실천율은 선택한 날짜에 존재하는 루틴 중 완료한 비율입니다. 연속 실천은 하루의 모든 루틴을 완료한 날을 기준으로 계산합니다.
- 브라우저 저장 공간을 비우거나 시크릿 창을 닫으면 저장 데이터가 없어질 수 있습니다.

## 주요 기능 테스트

1. 루틴 추가 후 이름과 카테고리가 목록에 표시되는지 확인합니다.
2. 완료 버튼을 누르면 오늘 완료 개수, 달성률, 진행률 막대, 주간 그래프가 바뀌는지 확인합니다.
3. 루틴을 수정하고 삭제해 목록과 통계가 갱신되는지 확인합니다.
4. 날짜를 하루 이전으로 이동해 완료 상태를 바꾸고, 오늘로 돌아갔을 때 오늘 기록이 그대로인지 확인합니다.
5. 브라우저를 새로고침해 루틴과 날짜별 완료 상태가 남아 있는지 확인합니다.
6. 모든 루틴을 삭제한 뒤 빈 상태의 추가 버튼이 동작하는지 확인합니다.
7. 개발자 도구의 모바일 화면 모드에서 좁은 화면의 레이아웃과 버튼을 확인합니다.

## GitHub에 올리기

GitHub에서 새 저장소를 만들고, README 안내에 따라 이 폴더를 저장소에 연결합니다. 기존 저장소가 아니라 새 저장소를 만들었다면 터미널에서 아래 명령을 프로젝트 폴더 안에서 실행합니다. `사용자명`과 `저장소명`은 자신의 값으로 바꿉니다.

```bash
git init
git add index.html style.css script.js README.md
git commit -m "Build DAYFLOW routine dashboard"
git branch -M main
git remote add origin https://github.com/사용자명/저장소명.git
git push -u origin main
```

이미 Git 저장소인 경우 `git init`과 `git remote add origin ...`은 반복하지 말고 기존 연결을 사용합니다.

## GitHub Pages 배포

1. GitHub 저장소에서 **Settings**를 엽니다.
2. 왼쪽 **Pages** 메뉴에서 **Build and deployment**의 Source를 **Deploy from a branch**로 설정합니다.
3. Branch는 `main`, 폴더는 `/(root)`를 선택하고 **Save**를 누릅니다.
4. Pages 설정 화면에 표시되는 배포 주소를 엽니다. 주소는 보통 `https://사용자명.github.io/저장소명/` 형태입니다.
5. 수정한 코드를 `main` 브랜치에 push하면 Pages가 다시 배포합니다. 첫 배포에는 몇 분 정도 걸릴 수 있습니다.

## 배포 후 문제 해결

- **페이지가 404로 나옵니다:** Pages의 브랜치가 `main`, 폴더가 `/(root)`인지 확인하고, 저장소 루트에 `index.html`이 있는지 확인합니다.
- **그래프가 나타나지 않습니다:** 인터넷 연결과 브라우저 개발자 도구의 네트워크 오류를 확인합니다. Chart.js는 CDN을 사용합니다.
- **변경한 화면이 바로 보이지 않습니다:** Pages 배포 상태가 완료됐는지 확인한 뒤 강력 새로고침을 합니다.
- **저장한 데이터가 보이지 않습니다:** 같은 브라우저와 같은 배포 주소인지 확인합니다. 로컬에서 연 페이지와 GitHub Pages는 서로 다른 저장 공간을 사용합니다.
- **스타일이나 스크립트가 로드되지 않습니다:** 파일 이름의 대소문자와 `index.html`의 상대 경로를 확인합니다. GitHub Pages에서는 대소문자가 구분됩니다.

## 참고

이 프로젝트는 별도의 백엔드 없이 동작하는 개인용 프로토타입입니다. 브라우저의 저장 데이터는 다른 사용자와 공유되지 않으며, 중요한 기록은 브라우저 데이터 삭제 전에 별도로 보관하세요.
